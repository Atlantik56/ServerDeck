# Настройка Server Deck

## Что потребуется

Для серверной части используйте отдельный Ubuntu 24.04 или Debian 12 с systemd и Python 3.10–3.12. Нужен доступ root либо пользователь с sudo. Текущая реализация проверки пароля использует модуль `crypt`; Python 3.13+ для сервера не поддерживается этой установкой.

На компьютере оператора для основного способа установки нужен OpenSSH Client; в Windows он доступен через «Параметры → Дополнительные компоненты». Python на этом компьютере не требуется: команда запускает bootstrap непосредственно на VPS. На Linux-хосте нужны Python 3.9–3.12, curl и доверенные CA-сертификаты. При отсутствии зависимостей bootstrap объясняет, что установить, и завершается.

Домен необязателен. Для доверенного сертификата понадобятся домен, email владельца для Let's Encrypt и доступ к DNS; входящие TCP 80 и 443 должны доходить до хоста панели. Без домена панель устанавливается по публичному IPv4 на свободный высокий HTTPS-порт с собственным сертификатом. SSH должен быть доступен компьютеру оператора. Установку выполняйте на отдельном хосте: мастер проверяет конфликты и не должен вытеснять существующий VPN или веб-сервер.

## DNS и HTTPS

Если домена пока нет, оставьте вопрос домена пустым. Укажите публичный IPv4 и при необходимости `--https-port` из диапазона 1024–65535; без него установщик выберет случайный свободный высокий порт. Разрешите входящие TCP-соединения к этому порту в firewall VPS и у провайдера. Мастер не открывает firewall автоматически.

Адрес будет иметь вид `https://192.0.2.10:ПОРТ/login/` — IP в примере замените своим. Браузер покажет предупреждение о собственном сертификате. До ввода кода первичной настройки сравните **SHA-256 fingerprint сертификата**, показанный установщиком через SSH, с отпечатком в сведениях сертификата браузера. Не подтверждайте неизвестный сертификат без сверки. PWA и встроенные панели с отдельными поддоменами требуют доверенного HTTPS-домена; их можно включить позднее.

Создайте A-запись, например `deck.example.org`, с публичным IPv4 хоста панели. Текущий мастер смены домена в панели подтверждает маршрут по IPv4 и отклоняет непроверенные AAAA-записи: перед сменой удалите AAAA для нового имени либо отдельно настройте и проверьте IPv6 административно. Наличие A-записи не подтверждает исправность опубликованного IPv6.

Для встроенных панелей создайте `*.deck.example.org`, направленную на тот же хост. Встроенный интерфейс использует отдельные имена вида `<идентификатор>-lucx.deck.example.org`, чтобы изолировать авторизацию и cookies. Это не домены управляемых VPN-серверов: менять их существующие адреса не требуется.

В режиме домена мастер получает основной сертификат через Certbot / Let's Encrypt, настраивает HTTPS в Caddy и автоматическое продление. HTTP-порт 80 остаётся нужен для ACME-проверок и переадресации на HTTPS. Для встроенных имён Caddy выпускает индивидуальные сертификаты по запросу только после разрешения имени серверной частью. DNS wildcard не является wildcard-сертификатом.

Выпуск доверенного сертификата зависит от DNS, доступности портов и лимитов Let's Encrypt. При ошибке выпуска мастер завершится с сообщением; отключать проверку TLS не следует. Чтобы перейти с IP на домен, заранее настройте DNS и порты, затем откройте настройки домена панели, проверьте показанный план и примените его. После изменения адреса войдите заново по новому HTTPS-домену и при необходимости переустановите PWA.

## Запуск мастера

В терминале Windows, macOS или Linux выполните команду, заменив `VPS` своим адресом:

```sh
ssh -t root@VPS "curl -fsSL https://raw.githubusercontent.com/Atlantik56/ServerDeck/main/install.sh | bash"
```

Если вы уже вошли на поддерживаемый Linux VPS:

```sh
curl -fsSL https://raw.githubusercontent.com/Atlantik56/ServerDeck/main/install.sh | bash
```

Для другого порта, SSH-пользователя или ключа добавьте соответствующие параметры `ssh -p ПОРТ -i ПУТЬ ПОЛЬЗОВАТЕЛЬ@VPS`. Сначала проверьте отпечаток хоста, как описано ниже. Bootstrap читает интерактивные вопросы из терминала; `ssh -t` нужен для его выделения.

Можно сначала скачать репозиторий, изучить скрипты и запустить `python3 install.py` из его каталога. Это альтернативный мастер для локального Linux или удалённого SSH-развёртывания с Windows/macOS/Linux; для этого варианта на компьютере оператора нужен Python 3 и OpenSSH (`ssh` и `scp`). Он оставляет стандартный ввод свободным: запуск `curl ... | python3` для него не подходит.

Мастер запрашивает:

1. Режим: локальный Linux или удалённый Linux VPS по SSH.
2. Для SSH: адрес, пользователя, порт и необязательный путь к приватному ключу на текущем компьютере.
3. HTTPS-домен и email владельца либо публичный IPv4 для запуска без домена.
4. Подтверждение показанного плана.

Установщик не запрашивает и не задаёт логин или пароль панели. В конце он один раз показывает случайный код первичной настройки со сроком один час. Откройте `/login/`, введите этот код и создайте собственные логин, пароль и подтверждение пароля. Только первый успешно завершённый запрос создаст учётную запись; код после этого недействителен. Существующая учётная запись не заменяется этим механизмом. Пароль хранится в виде bcrypt-хеша, а код на сервере — в виде хеша.

Не помещайте пароль или код настройки в shell-команды, URL, скриншоты и публичные сообщения. Приватный SSH-ключ, с которым Python-мастер подключается к хосту установки, остаётся на компьютере оператора и не добавляется в реестр управляемых VPS.

Список точных параметров установленной версии:

```sh
python3 install.py --help
```

Проверка плана без установки:

```sh
python3 install.py --dry-run
```

Сухой запуск проверяет и показывает конфигурацию установки; он не заменяет реальный выпуск сертификата или проверку доступности домена из интернета.

Параметры Python-мастера можно передать явно:

```sh
python3 install.py --mode ssh --host server.example.org --user root --port 22 --identity /путь/к/ключу --domain deck.example.org --email admin@example.org --dry-run
```

`--yes` подтверждает показанный план без отдельного вопроса. Параметров `--admin` и `--password` нет: учётная запись создаётся владельцем в браузере. `--public-ip` задаёт IPv4 установки, `--https-port` — высокий порт для режима без домена. `--source /путь/к/распакованному/проекту` позволяет использовать изученную локальную копию исходников. Без него мастер использует соседние исходники, если они есть, либо загружает архив проекта с GitHub. Для воспроизводимой установки сначала скачайте нужный commit и укажите этот каталог через `--source`.

## Проверка SSH-отпечатка

При первом входе сравните fingerprint хоста с данными консоли провайдера или иным доверенным каналом. Не подтверждайте неизвестный отпечаток автоматически и не отключайте `StrictHostKeyChecking`.

Пример первого ручного подключения:

```sh
ssh -p 22 -i /путь/к/вашему/ключу root@server.example.org
```

Адрес, порт и путь в примере замените своими. Если fingerprint изменился у уже известного сервера, сначала установите причину через консоль провайдера. Удаление записи `known_hosts` само по себе не подтверждает подлинность сервера.

## После установки

Откройте адрес `/login/`, показанный установщиком, создайте собственную учётную запись с одноразовым кодом и войдите. В IP-режиме сначала проверьте fingerprint сертификата. Установка не содержит серверов автора, предварительно настроенных VPN, Telegram-бота или ключей доступа к чужим хостам.

Если код потерян или истёк, до создания первой учётной записи выполните на VPS из доверенной root/sudo-сессии:

```sh
sudo python3 /usr/local/lib/server-deck/reset_bootstrap.py
```

Это интерактивно выдаст новый код на час только при пустом хранилище учётных записей. После создания аккаунта этот способ больше не работает. Для намеренного восстановления доступа существующего владельца предусмотрена отдельная root-команда:

```sh
sudo python3 /usr/local/lib/server-deck/reset_account.py
```

Она запрашивает логин и новый пароль локально в терминале; используйте её только для восстановления доступа. Не заменяйте файл аккаунтов вручную и не запускайте повторную установку ради сброса пароля.

Если первичная настройка была уже начата, защитный маркер `bootstrap-used` блокирует повторное создание владельца даже после удаления файла аккаунтов. Обычный сброс кода такой маркер не снимает. Только для проверенной незавершённой настройки без аккаунтов предусмотрен `reset_bootstrap.py --recover-incomplete-setup`: он требует явного подтверждения имени хоста. Все операции восстановления используют тот же межпроцессный lock, что и создание владельца в браузере.

Служебные операции смены пароля и настройки домена используют ограниченные root-helper через локальный SSH. Если действующая SSH-политика запрещает этот вход, установщик не ослабляет её: соответствующие функции интерфейса могут быть недоступны. Проверьте сообщение установщика и настройте разрешённый локальный доступ административно либо используйте ручной root/sudo-путь; настройка чужих VPN-серверов для этого не требуется.

Добавьте VPS через «Добавить сервер». Генератор создаёт отдельную пару Ed25519. Скопируйте в консоль целевого VPS команду установки публичного ключа, затем проверьте host key и соединение. Для применения операций панели удалённому пользователю нужны права на соответствующие команды; полный набор функций рассчитан на административный SSH-доступ Linux.

Не отключайте парольный SSH-вход на целевом сервере, пока не проверили вход ключом и зависимость используемых приложений от текущей схемы авторизации. Server Deck не требует отключения пароля только ради добавления хоста.

Подключайте обнаруженные LucX / 3x-ui и MTProxyL в разделе панелей. Автоматический вход зависит от поддерживаемой версии и возможности получить действующие учётные данные по административному SSH. Включённую стороннюю 2FA панель не обходит. Произвольные веб-приложения можно добавить ссылкой; для них универсальный автоматический вход не обещается.

## Telegram

Создайте собственного бота через BotFather. В текущей версии интерфейс привязывает получателя и настраивает события, а токен читает из защищённого файла на контроллере. Сохраните его из доверенной root/sudo-сессии следующей командой: ввод скрыт, токен не передаётся аргументом и не попадает в историю shell.

```sh
sudo python3 - <<'PYTOKEN'
import getpass, os, pathlib, pwd, re, tempfile
owner = pwd.getpwnam('serverdeck')
root = pathlib.Path('/var/lib/serverdeck')
if root.is_symlink() or not root.is_dir():
    raise SystemExit('Проверьте каталог установленной панели')
token = getpass.getpass('Токен собственного Telegram-бота: ')
if not re.fullmatch(r'[0-9]{5,16}:[A-Za-z0-9_-]{20,100}', token):
    raise SystemExit('Неверный формат токена')
fd, name = tempfile.mkstemp(prefix='.telegram-', dir=str(root))
try:
    os.fchmod(fd, 0o600)
    os.fchown(fd, owner.pw_uid, owner.pw_gid)
    with os.fdopen(fd, 'w') as out:
        out.write(token + '\n')
        out.flush()
        os.fsync(out.fileno())
    os.replace(name, root / 'telegram.token')
finally:
    if os.path.exists(name):
        os.unlink(name)
print('Токен сохранён без вывода его значения')
PYTOKEN
```

После этого откройте настройки уведомлений, включите бота и привяжите свой личный чат по показанной одноразовой ссылке. Панель перечитывает файл токена; перезапуск VPN или контроллера для этого не нужен. Если администратор изменил `DECK_TELEGRAM_TOKEN_FILE`, используйте установленный им путь вместо стандартного. Не сохраняйте токен в Git, URL, скриншотах или открытых логах.

Для спокойного мониторинга оставьте критические события: недоступность сервера, остановка AWG или MTProxyL и восстановление. Меню позволяет запросить текущий статус. Перезапуск выбранной службы или VPS требует отдельного подтверждения; он может кратко прервать подключения.

## Резервные копии

Создайте первую резервную копию и сохраните **ключ восстановления отдельно от архивов**. Без него зашифрованные копии непригодны для восстановления. Резервная копия конфигурации панели или хоста не является полным образом диска либо доказательством успешного восстановления.

Локальное расшифрование:

```sh
python3 recover_backup.py --backup /путь/backup.sdbackup --key /путь/server-deck-recovery.key --out /путь/новый-каталог
```

Команда не подключается к VPS. Каталог результата должен быть новым; извлечённые данные содержат секреты. Перед восстановлением на рабочий сервер изучите план, версию панели и адрес назначения: восстановление может заменить настройки и прервать подключения.

## Проверка установки и обслуживание

Проверьте статус служб Server Deck, вход через HTTPS, добавление первого VPS и создание копии. На хосте установки:

```sh
systemctl status server-deck.service server-deck-auth.service caddy.service --no-pager
```

В режиме домена состояние и журналы обновления сертификата можно проверить штатными командами Certbot и systemd. До ручного теста обновления изучите имя установленного timer и deploy hook в конфигурации этой версии. Повторный выпуск сертификатов без причины может исчерпать лимиты Let's Encrypt. В IP-режиме Let's Encrypt и автоматическое доверие браузера не используются.

Установщик не служит безусловным обновлением уже работающей панели. Перед заменой исходников сохраните реестр, SSH-ключи, конфигурацию входа, состояние сессий, ключ восстановления и рабочие данные; меняйте их отдельно от публичного кода. Не запускайте новую установку поверх существующей с ожиданием автоматического переноса секретов.

Серверные ОС, маршрутизация, DNS и доступ из конкретной сети проверяются в реальной среде. Сухие тесты установщика не являются испытанием на физической Windows, macOS, Android или во всех облачных провайдерах.

Если смена домена завершилась с неопределённым результатом или возврат прежних настроек не подтверждён, панель сохраняет защитный файл `/opt/server-deck/control-data/deployment-freeze` и временно блокирует дальнейшие изменения. Не удаляйте его для обхода ошибки. Из доверенной root/sudo-сессии изучите состояние обработчика:

```sh
printf '{"action":"inspect"}' | sudo python3 -I /usr/local/lib/server-deck/deployment_helper.py
```

Проверка состояния сама не снимает блокировку. Администратору нужно сопоставить идентификатор задачи с `server-deck-domain-<jobid>`, проверить Caddy, службы авторизации и панели, итоговый HTTPS-адрес и запись результата. Только после подтверждённого завершения или возврата можно вручную снять блокировку соответствующей задачи. Автоматического повторного применения нет.
