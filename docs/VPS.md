# VPS для размещения Server Deck

Для группы из шести управляемых серверов рекомендуем **отдельный VPS: 2 vCPU, 4 ГБ RAM, 40 ГБ SSD/NVMe, постоянный публичный IPv4 и Ubuntu Server 24.04 LTS**. Это отправная точка с запасом для административных задач, а не результат нагрузочного теста и не обещание производительности при любом количестве клиентов и архивов.

Панель передаёт команды и собирает состояние через SSH. Обычный трафик пользователей AWG/MTProxyL проходит через соответствующие VPN/прокси-серверы. Нагрузка панели зависит прежде всего от числа опрашиваемых хостов, открытых встроенных панелей и операций с резервными копиями.

## Ресурсы

| Параметр | Экономичный старт | Рекомендуется для шести VPS |
| --- | --- | --- |
| Процессор | 1 vCPU | 2 vCPU |
| Оперативная память | 2 ГБ | 4 ГБ |
| Системный диск | 20 ГБ SSD с контролем свободного места | 40 ГБ SSD/NVMe с возможностью расширения |
| Виртуализация | Полноценная Linux VM с systemd | KVM или аналогичная VM, отдельный экземпляр под панель |
| Архитектура | amd64/x86_64 как простой исходный выбор | amd64/x86_64 |
| Адрес | Постоянный публичный IPv4 | Постоянный публичный IPv4 и управляемый DNS |
| Доступ к восстановлению | Консоль провайдера | Консоль, rescue-режим и снимки VM |

Экономичный вариант имеет смысл при небольших копиях и редких изменениях. После установки проверьте пиковое потребление RAM во время резервного копирования, время SSH-опросов и остаток диска; при необходимости увеличьте ресурсы. Установщик не измеряет допустимую нагрузку по объёму RAM и не резервирует место для будущих копий.

**Почему нужен запас памяти.** Сейчас архив создаётся и проверяется целиком: в процессе одновременно могут существовать исходные данные, представление Base64, зашифрованная копия и результат проверочного расшифрования. Для архивов LucX/MTProxyL в адаптере предусмотрен предел 24 МиБ, однако это предел размера конкретного архива, а не предел памяти процесса и не лимит всех данных на диске. Своп может смягчить короткий пик, но постоянная работа в свопе означает, что ресурсов мало.

**Почему SSD важнее большого числа ядер.** История здоровья и статистика защиты хранятся в SQLite. Пиковая работа включает чтение и запись архивов, хеширование и шифрование. Для небольшой группы VPS сначала важны нормальная задержка диска, доступная RAM и стабильный сетевой маршрут.

## ОС и совместимость

Установщик этой версии принимает **Ubuntu 24.04** и **Debian 12** с systemd, APT и Python 3.9–3.12. Для новой установки предпочтительна Ubuntu Server 24.04 LTS. Серверной средой не являются Windows, macOS, Alpine, обычный Docker-контейнер без systemd или другая версия Linux только потому, что она новее.

Ubuntu 24.04 имеет стандартное сопровождение безопасности до 31 мая 2029 года. Актуальный срок проверяйте в [официальных release notes Ubuntu](https://documentation.ubuntu.com/release-notes/24.04/).

Debian 12 уже заменён Debian 13 в линейке релизов Debian; для Bookworm действует LTS до 30 июня 2028 года с ограничениями по архитектурам. Поддержка Debian 12 в установщике не означает автоматическую совместимость с Debian 13. См. [информацию Debian о Bookworm](https://www.debian.org/releases/bookworm/).

Ограничение Python связано в том числе с текущей реализацией проверки паролей через системный `crypt`/bcrypt. Не заменяйте системный Python и не обходите проверку версии ради установки. Поддержку следующего дистрибутива следует добавлять вместе с проверкой его пакетов, авторизации и служб.

Управлять установкой и пользоваться панелью можно с Windows, macOS или Linux через OpenSSH и браузер. Android поддерживается через браузер/PWA; для PWA нужен доверенный HTTPS-домен. Команды приведены в [инструкции установки](SETUP.md).

## Отдельный сервер для панели

Выделите под Server Deck отдельную VM. На ней будут ключи управляемых VPS, реквизиты панелей, токен Telegram и ключ восстановления архивов. Администратор этого хоста получает значительный доступ ко всей подключённой инфраструктуре.

Не совмещайте контроллер с публичным тестовым сайтом, сторонним ботом, приложением неизвестного происхождения или общим хостингом других пользователей. Сервис обновления и установка компонентов выполняют привилегированные операции; учётную запись панели можно давать только доверенным администраторам.

Установка рассчитана на чистый хост: существующие Caddy/Nginx, занятые порты и каталоги установки могут вызвать отказ до применения изменений. Освобождать порт остановкой работающего VPN или веб-сервера для панели не нужно — выберите другую VM.

Для шести серверов обычная отдельная VM соответствует текущей архитектуре. Kubernetes не является требованием установки. Несколько одновременно работающих экземпляров Server Deck с общим каталогом данных не реализуют готовый кластер: SQLite, очереди, сессии и ключи требуют отдельного проектирования отказоустойчивости.

## Россия или зарубежная площадка

Место выбирайте по трём реальным маршрутам:

1. Ваш браузер → HTTPS панели.
2. Панель → SSH каждого управляемого VPS.
3. Панель → источники пакетов, GitHub/GitLab, ACME, Telegram и внешние проверки.

Площадка в РФ может быть удобна при основном доступе из российских сетей; зарубежная — при преимущественно зарубежной инфраструктуре. Перед долгой оплатой проверьте перечисленные маршруты из тех сетей, которыми будете пользоваться. Название страны само по себе не подтверждает доступность, низкую задержку или отсутствие фильтрации. Учтите также доступ к кабинету провайдера, способ оплаты и возможность восстановить VM без SSH.

Не выбирайте хост панели одновременно в качестве единственной точки измерения блокировок из РФ. Успешное соединение с зарубежного VPS показывает доступность по его маршруту. Для собственной проверки именно из РФ нужна отдельная точка в российской сети с подтверждённой географией выхода; временный Mac подходит только пока доступен и измеряет нужный маршрут. Cheburcheck — независимый внешний источник, а его вердикты относятся к ответившим зондам.

Потеря SSH, ошибка ключа и блокировка IP — разные события. Автодиагностика панели помогает их сопоставить, но не устанавливает причину по одному тайм-ауту. Проверка TCP не подтверждает работоспособность UDP/AWG.

## Адреса, домен и порты

Стабильный публичный IPv4 упрощает DNS, доступ к панели и исключения Fail2ban на управляемых хостах. IPv6 можно рассматривать дополнительно, однако текущий мастер публичного адреса и смены домена основан на подтверждённом IPv4. Не рассчитывайте на установку через IPv6-only VPS.

Для постоянного использования заведите, например, `deck.example.org`. Направьте его A-запись на IPv4 контроллера. Встроенным панелям с отдельными именами нужен также DNS для `*.deck.example.org`. Wildcard-запись DNS не означает, что основной Certbot-сертификат автоматически становится wildcard-сертификатом: у встроенных панелей свой предусмотренный маршрут выпуска сертификатов через Caddy.

В текущем помощнике смены домена неподтверждённая AAAA-запись блокирует применение. Удалите такую запись либо дождитесь поддержки и проверки IPv6 в проекте; иначе часть клиентов или проверяющих систем может обращаться по другому адресу.

| Направление | Порты | Назначение |
| --- | --- | --- |
| Входящий TCP | 22 или выбранный SSH-порт | Администрирование контроллера |
| Входящий TCP, режим домена | 80 и 443 | Проверка ACME/HTTP и HTTPS панели |
| Входящий TCP, режим без домена | Выбранный мастером свободный высокий порт | HTTPS по IP с собственным сертификатом |
| Исходящий TCP | SSH-порты управляемых VPS | Мониторинг, управление и туннели встроенных панелей |
| Исходящий TCP | 443, а для используемых APT-зеркал также их HTTP/HTTPS-порты | API, загрузки, сертификаты, Telegram, внешние проверки |
| Доступ к резолверу | Порты используемой службы DNS | Разрешение доменных имён |
| Только loopback | 8765, 8766, 8768 | Приложение, маршрутизатор встроенных панелей и служба входа |

Не публикуйте 8765/8766/8768 наружу. Установщик не открывает firewall провайдера или вашей ОС: настройте разрешения под выбранный режим отдельно, сохранив текущий SSH-доступ.

При доменной установке Certbot использует HTTP-01/webroot: проверяющая система должна получить файл по HTTP на порту 80. Ограничение порта 80 только своим IP помешает этой проверке. См. [руководство Certbot](https://eff-certbot.readthedocs.io/en/stable/using.html#webroot) и [описание HTTP-01 в Let’s Encrypt](https://letsencrypt.org/docs/challenge-types/#http-01-challenge).

Если оставить домен пустым, панель получит свободный случайный HTTPS-порт и собственный сертификат. Сверьте его отпечаток через SSH до ввода одноразового кода настройки. Позднее подключите домен в настройках панели; действующая учётная запись и реестр сохраняются. План смены адреса показывает воздействие и требует подтверждения.

## Сколько места оставить под копии

Объём SSD выбирайте вместе с политикой хранения. Измерения здоровья и события защиты в текущей реализации удерживаются за семь дней, однако резервные копии не удаляются автоматически по этому сроку. Размер файла SQLite также не обязан сразу уменьшаться после удаления старых строк.

Оценка запаса:

```text
диск = ОС и пакеты + данные панели + архивы + временные файлы + свободный запас
архивы ≈ число серверов × копии на сервер × средний размер копии
```

Например, 6 серверов × 30 сохранённых копий × 20 МиБ дают около 3,5 ГиБ только архивов. Это иллюстрация расчёта, а не обещанный размер: копии перед изменениями увеличивают количество, а разные панели имеют разный состав данных. К этому прибавляются история, логи, системные обновления и временные файлы проверки архивов. Оставляйте примерно 20–30% диска свободными и пересматривайте запас после первого месяца эксплуатации.

Проверки на установленном контроллере:

```sh
df -h /opt
sudo du -sh /opt/server-deck/control-data/backups /opt/server-deck/health.sqlite3
systemctl is-active server-deck.service server-deck-auth.service caddy.service
```

Не удаляйте рабочие файлы SQLite и архивы через случайный `rm`. Сначала сохраните нужные копии, определите политику хранения и проверьте, какие файлы относятся к действующей установке.

## Резервирование самого контроллера

Копии LucX/MTProxyL в панели не являются полным резервным образом Server Deck или VM. Для восстановления контроллера нужны отдельные копии его реестра, служебных настроек, SSH-ключей, хранилища архивов, ключа восстановления и аккаунтов/сессий. Для доменного режима учитывайте конфигурацию Caddy и TLS/ACME-данные.

Практическая схема:

- Снимок VM перед изменениями ОС, диска или схемы развёртывания.
- Зашифрованная копия данных контроллера вне этой VM; расписание настраивается отдельно.
- Ключ восстановления архивов отдельно от самих архивов и с проверенным способом получения.
- Хотя бы одна проверка восстановления на отдельной машине.

Снимок у того же провайдера полезен для отката, но не заменяет независимую копию. Если архивы и ключ расшифрования доступны на одном скомпрометированном контроллере, шифрование файлов само по себе не изолирует их от его администратора. Рабочее состояние не должно попадать в Git. См. [модель доступа](SECURITY.md).

## Доступ и обслуживание

Для нового выделенного контроллера используйте отдельный административный SSH-ключ и уникальный пароль панели. Перед ужесточением SSH проверьте вход ключом во второй сессии и доступ к rescue-консоли. Параметры парольной и ключевой аутентификации описаны в [руководстве OpenSSH](https://man.openbsd.org/sshd_config).

Не применяйте отключение парольного SSH ко всем управляемым VPS как часть настройки контроллера: у существующих способов управления Amnezia может быть своя зависимость от него. Изменения SSH делайте адресно. Установщик сохраняет действующую SSH-политику, а редактор Fail2ban меняет только поддерживаемые параметры jail `sshd`; это отдельные операции.

Служебным помощникам установки нужен доступ по ограниченному SSH-ключу на loopback. После изменения firewall, `AllowUsers` или правил входа проверьте не только обычный SSH, но и смену пароля панели/чтение настроек домена. Не расширяйте права служебных ключей до обычного неограниченного входа ради устранения ошибки.

Первичный установщик после подтверждения плана и проверки чистого хоста обязательно выполняет APT update и upgrade ОС, затем устанавливает недостающие зависимости. Заранее обеспечьте доступ к зеркалам APT и запас диска; подробнее — [этап подготовки ОС](SETUP.md#обязательное-обновление-ос-и-зависимости). Пакетные скрипты могут перезапускать службы, а автоматической перезагрузки VM установщик не делает. Последующие обновления, требующие перезапуска компонентов или VM, планируйте с резервной копией и проверкой после выполнения. Для самой панели поддерживайте включёнными systemd-службы и предусмотренный таймер продления сертификатов. Обновление ОС и смена её major-версии — разные процедуры; новая major-версия должна быть явно поддержана установщиком.

Контроллер — единая точка управления и уведомлений. Если он выключен или потерял сеть, его собственный бот может перестать присылать сообщения. Для обнаружения такого случая нужен внешний монитор HTTPS/доступности у независимого наблюдателя. Такая проверка не создаётся автоматически установщиком и не означает готовое аварийное переключение.

## Перед выбором тарифа

Проверьте у провайдера возможность увеличить RAM/диск, получить rescue-консоль и экспортировать резервную копию. Для небольшой инфраструктуры стабильность SSH/HTTPS и восстановление важнее большого обещанного числа ядер. Сначала выбирайте короткий срок оплаты и проверяйте реальные маршруты; затем переходите на длительный тариф, если результаты подходят.

Версия рекомендаций: **4 ноября 2026 года**. Сроки сопровождения ОС и условия провайдера меняются; перед новой установкой перепроверьте официальные источники и поддерживаемые версии в установщике.
